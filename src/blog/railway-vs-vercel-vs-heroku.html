Heroku was my PaaS provider for years. I have fully switched to Railway. I really like Vercel. This is a high-level feature comparison with my usage baked in.

The short version: Railway handles anything I throw at it for normal app work. The only gap is GPU, and for that I spin up a service on Modal.

What each one is for

Heroku is the classic PaaS shape: git push, dynos, add-ons, web and worker processes. Predictable. Still fine for that model.

Vercel is strongest as a frontend platform: preview deployments, Next.js defaults, CDN delivery, serverless functions beside the UI. If most of the product is the web app and light API surface, it is a great fit.

Railway is built around running a full service graph: APIs, workers, databases, and long-running processes in one project. You bring the architecture instead of reshaping everything into functions.

Feature comparison

  • App shape — Heroku: web + worker dynos. Vercel: frontend + serverless/edge functions. Railway: multiple long-running services that talk to each other.
  • Databases — Heroku: add-on marketplace, Postgres as a common default. Vercel: usually an external or partner database. Railway: databases sit beside the services in the same project.
  • Long-running processes — Heroku: yes. Vercel: not the focus; sockets, queues, and heavy workers usually live elsewhere. Railway: yes.
  • Frontend DX — Vercel leads: previews, framework awareness, edge delivery. Railway can host frontends. Vercel is still the specialist here.
  • Mixed stacks — Heroku covers the classic dyno split. Vercel covers frontend-first architectures. Railway covers monorepos with several services and data stores without leaving the platform.
  • GPU — Not what I use any of these three for. Modal covers that lane.

How I place them

Heroku trained a lot of us on PaaS. I am not putting new systems there.

Vercel stays in rotation when the job is frontend delivery and preview workflow. I like it. It is not my default for the whole backend.

Railway is the default. APIs, workers, databases, real-time servers, static frontends when I want them in the same place. So far it has taken every non-GPU workload I have given it.

Standings

  • Railway — default for full applications; GPU is the only gap in my setup.
  • Vercel — best frontend and preview experience of the three.
  • Heroku — former default; not where I deploy now.
  • Modal — GPU jobs.

Use Vercel when the product is mostly the frontend. Use Railway when you need the rest of the system to live next to it. Keep GPU somewhere built for GPU.
