These are some of my favorite server and framework choices and the quality tooling I pair with them. They are not the only choices, but they are the ones I reach for most often.

Prisma, OpenAPI, Zod

With those three, the system stays grounded. Prisma for the data model, OpenAPI for the HTTP contract, Zod for validation and typed shapes. One place for what exists, what can be sent, and what is valid.

Servers

Fastify or similar is the least friction for me. Helmet and Passport cover security headers and auth when I need them.

Next is an open question. Useful when the product wants routing, rendering, and deploy conventions together. Less useful when I want a plain API, a Vite app, or a generator that already owns those seams.

If we are using my generator YAML architecture, the opinions live in the pipeline. Otherwise we should adopt a framework to keep us honest for any larger projects.

Serve the UI or detach it

Both work. Detached frontends help with separate deploys, scaling, and multi-platform clients. Unless you are building for mobile or multi-platform, same-host serving usually wins: one origin, simpler auth, less CORS, fewer environment mismatches.

Frontend

Angular is where most of my professional experience is, but it feels dated for new work. Post-AI, my independent projects are React and Vite. After that, vanilla or React Native. Zod already puts us in TypeScript.

Quality

ESLint for static analysis. Fallow for dead code, duplication, and structural drift. Add e2e tests and the system stays pretty solid.

Summary

Prisma, OpenAPI, Zod. Fastify with Helmet and Passport as needed. Generator pipeline or StrongLoop-style opinions. Same-host UI unless mobile or multi-platform requires a split. React and Vite on the web, vanilla or React Native when that fits. TypeScript, ESLint, Fallow, and e2e.
