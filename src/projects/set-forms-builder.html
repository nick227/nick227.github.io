Builder state is a normalized tree of field descriptors, with an undo/redo command stack that tracks every change as a reversible object, similar to how design tools handle history. Rendering is a separate concern — the renderer takes JSON Schema and produces accessible, validated HTML without any knowledge of the builder that generated it. Any standard validator, like Ajv or Zod, can consume that schema output directly.

The problem came from watching engineering time go into repetitive form implementations. I designed the UX, built the command-stack state model, and wrote the builder and renderer from scratch, then confirmed the output schema worked with the backend services that would consume it.
